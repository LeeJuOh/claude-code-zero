# Agent Extension Visual — JSON Data Schema

This document defines the JSON structure for `sections-data.json`. The visual-report-writer outputs this file; the `render-sections.js` script converts it into HTML section files with correct CSS class names.

**Key principle**: Focus on content, not presentation. The render script handles all HTML structure, CSS classes, Mermaid wrappers, zoom controls, and chart containers. You only provide the data.

---

## Top-level Structure

```json
{
  "metadata": { ... },
  "source_context": { ... },
  "sections": {
    "header": { ... },
    "overview": { ... },
    "architecture": { ... },
    "feature_deep_dive": { ... },
    "environment_fit": { ... },
    "usage_guide": { ... },
    "components": { ... },
    "security_audit": { ... },
    "dependencies": { ... },
    "plugin_profile": { ... },
    "footer": { ... }
  }
}
```

---

## metadata (required)

Same fields as the existing HTML mode's metadata.json. The render script passes these through to the assembler.

| Field | Type | Description |
|-------|------|-------------|
| `lang` | string | Language code: "en", "ko", "ja", etc. |
| `title` | string | Report title, e.g. "Agent Extension Visual: plugin-name" |
| `font_link` | string | Google Fonts `<link>` tag (stylesheet only, no preconnect) |
| `css_variables` | string | CSS variable overrides: `--font-heading: ...; --font-body: ...; --accent: ...;` |
| `css_variables_dark` | string | Dark mode overrides: `--accent: ...;` |
| `mermaid_theme` | string | Additional Mermaid themeVariables (usually empty) |

**Note**: `toc_content` and `chart_data` are auto-generated by the render script from the sections data. Do NOT include them.

---

## source_context (optional)

Passed through from the orchestrator. Used for generating source links on component cards.

| Field | Type | Description |
|-------|------|-------------|
| `type` | string | `"local"` or `"github"` |
| `base` | string | Absolute path to plugin root |
| `github_url` | string | GitHub web URL base (only when type is "github") |

## sections.header

| Field | Type | Description |
|-------|------|-------------|
| `plugin_name` | string | Plugin display name |
| `subtitle` | string | Optional subtitle (default: "Agent Extension Visual Report") |
| `version` | string | Plugin version |
| `author` | string | Plugin author |
| `date` | string | Generation date |
| `risk_level` | string | `"critical"`, `"high"`, `"medium"`, or `"low"` |

---

## sections.overview

| Field | Type | Description |
|-------|------|-------------|
| `heading` | string | Optional section heading (default: "Plugin Overview") |
| `summary` | string | 2-3 sentence at-a-glance summary |
| `what` | string | What the plugin does |
| `how` | string | How it works |
| `unique` | string | What makes it different |
| `features` | string[] | Key feature list |
| `kpis` | array | KPI stat cards (see below) |
| `chart` | object | Component chart data (see below) |
| `pattern` | string | Primary pattern description |
| `target_users` | string | Target user description |

### kpis[]

| Field | Type | Description |
|-------|------|-------------|
| `value` | string\|number | Display value |
| `label` | string | Label text |
| `variant` | string | `"success"`, `"danger"`, `"info"`, or `"warning"` |

### chart

| Field | Type | Description |
|-------|------|-------------|
| `type` | string | Chart.js type: `"doughnut"`, `"bar"`, `"pie"` |
| `labels` | string[] | Chart labels |
| `data` | number[] | Chart data values |
| `colors` | string[] | Optional custom colors (auto-generated if omitted) |

## sections.architecture

| Field | Type | Description |
|-------|------|-------------|
| `heading` | string | Optional section heading |
| `narrative` | object | Problem/insight/thesis/constraints (see below) |
| `philosophy` | array | Design philosophy cards |
| `diagrams` | array | Mermaid diagrams |

### narrative

| Field | Type | Description |
|-------|------|-------------|
| `problem` | string | User pain point |
| `core_insight` | string | Non-obvious understanding |
| `design_thesis` | string | Fundamental approach |
| `constraints` | string | Intentional refusals |

### philosophy[]

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Principle name |
| `description` | string | 2-3 sentence explanation |
| `example` | string | Concrete codebase reference |

### diagrams[]

| Field | Type | Description |
|-------|------|-------------|
| `title` | string | Diagram heading (e.g. "Component Relationships") |
| `mermaid` | string | Raw Mermaid diagram code |
| `size` | string | Optional: `"compact"`, `"default"`, or `"tall"` |

**Mermaid rules still apply**: Use `<pre class="mermaid">` syntax in the raw code. Use 8-digit hex for fills in classDef (`fill:#0891b226`), never `rgba()`. Never set `color:` in classDef. Add `click NodeId "#section-id"` for in-report navigation.

## sections.feature_deep_dive

| Field | Type | Description |
|-------|------|-------------|
| `heading` | string | Optional section heading |
| `lead` | string | Lead paragraph text |
| `mechanisms` | array | Mechanism cards |
| `workflow_trace` | array | Primary workflow steps |
| `tutorial_scenarios` | array | Practical guide scenarios |

### mechanisms[]

| Field | Type | Description |
|-------|------|-------------|
| `title` | string | "{Principle}: {How It's Enforced}" |

| `steps` | array | Implementation chain steps |
| `code_pattern` | object | Optional code snippet |

| `best_practice` | string | Tip for users |

### mechanisms[].steps[]

| Field | Type | Description |
|-------|------|-------------|
| `text` | string | Step description |
| `source_link` | object | Optional: `{ "path": "relative/path", "label": "display text" }` |

### mechanisms[].code_pattern

| Field | Type | Description |
|-------|------|-------------|
| `language` | string | Programming language for syntax highlighting |
| `code` | string | Code snippet (will be HTML-escaped by render script) |

### workflow_trace[]

| Field | Type | Description |
|-------|------|-------------|
| `title` | string | Step title |
| `description` | string | Step description |
| `source_link` | object | Optional: `{ "path": "relative/path" }` |

### tutorial_scenarios[]

| Field | Type | Description |
|-------|------|-------------|
| `title` | string | Scenario title |
| `steps` | array | `[{ "user_action": "...", "behind_scenes": "..." }]` |
| `tips` | string[] | Best practice tips |

## sections.environment_fit

Standalone diagnosis section. When verdict is RECOMMENDED with no findings, provide minimal data (verdict + verdict_summary only).

| Field | Type | Description |
|-------|------|-------------|
| `heading` | string | Optional section heading |
| `verdict` | string | `"RECOMMENDED"`, `"CONDITIONAL"`, `"REDUNDANT"`, or `"CONFLICTING"` |
| `verdict_summary` | string | 1-2 sentence diagnosis |
| `installation_status` | object | `{ "status": "NEW\|ALREADY_INSTALLED", "detail": "..." }` |
| `context_budget` | object | See below |
| `dependency_check` | object | See below |
| `overlap` | array | Functional overlap findings |
| `trigger_collisions` | array | Trigger collision findings |
| `hook_impact` | object | Hook impact analysis |
| `component_deps` | array | Component dependency findings |
| `recommendations` | string[] | Actionable recommendations |

### context_budget

| Field | Type | Description |
|-------|------|-------------|
| `rows` | array | `[{ "resource", "current", "adding", "budget_200k", "budget_1m", "severity" }]` |
| `note` | string | Optional context budget notes |

### dependency_check

| Field | Type | Description |
|-------|------|-------------|
| `status` | string | `"READY"`, `"PARTIAL"`, or `"ACTION_NEEDED"` |
| `severity` | string | `"low"`, `"medium"`, or `"high"` |
| `items` | array | `[{ "name", "type", "required": bool, "status": "AVAILABLE\|MISSING", "help" }]` |

### overlap[]

`[{ "this_skill", "existing_skill", "classification": "DUPLICATE\|OVERLAP\|COMPLEMENT\|UPGRADE", "detail" }]`

### trigger_collisions[]

`[{ "severity": "high\|medium", "this_skill", "existing_skill", "description" }]`

### hook_impact

`{ "rows": [{ "metric", "current", "adding", "projected", "severity" }] }`

### component_deps[]

`[{ "component", "depends_on", "type", "status": "AVAILABLE\|MISSING" }]`

## sections.components

Tab-based component listing. The render script generates the tab UI automatically.

| Field | Type | Description |
|-------|------|-------------|
| `heading` | string | Optional section heading |
| `skills` | object | `{ "active": ComponentCard[], "reference": ComponentCard[] }` |
| `agents` | ComponentCard[] | Agent component cards |
| `commands` | ComponentCard[] | Command component cards |
| `hooks` | ComponentCard[] | Hook component cards |
| `mcp` | ComponentCard[] | MCP server cards |
| `lsp` | ComponentCard[] | LSP server cards |

### ComponentCard

| Field | Type | Description |
|-------|------|-------------|
| `name` | string | Component name |
| `description` | string | Brief description |
| `source_path` | string | Relative path for source link |
| `meta` | array | `[{ "label": "...", "value": "..." }]` — key-value metadata rows |
| `raw_content` | string | Optional raw content excerpts (shown in collapsible) |

## sections.plugin_profile

| Field | Type | Description |
|-------|------|-------------|
| `heading` | string | Optional section heading |

| `scripts` | string | `"pass"` or `"fail"` (has scripts) |
| `hooks` | string | `"pass"` or `"fail"` (has hooks) |
